# m13 — Specification of the `.m13` scene descriptor format

**Version:** 0.1
**Status:** Drafted · Phase 1 deliverable
**Authored:** 2026-05-21
**Maintainer:** NeoNodos · Genaro Isaí García Torres
**Source of truth (code):** [`packages/runtime/src/parser/schema.ts`](../packages/runtime/src/parser/schema.ts)
**JSON Schema export:** [`v0.1.schema.json`](./v0.1.schema.json)

---

## 1. Identidad y propósito

Un archivo `.m13` describe **una escena 3D habitable como YAML semántico**. No declara polígonos, texturas ni bundles — declara **qué hay** en el espacio (paredes, piso, techo, objetos, luz, ambiente). El motor `@m13/runtime` sintetiza geometría y materiales en GPU a partir de esta descripción.

Una escena válida pesa típicamente entre **1 y 30 KB**. El compilador la convierte a un módulo WGSL ejecutable por WebGPU.

### Filosofía de diseño

- **Semántica antes que geométrica.** Decir `concept: pared_ladrillo_viejo`, no `mesh: brick_wall_v3.fbx`.
- **YAML porque es legible por humanos.** Soporta comentarios. Editable a mano por diseñadores.
- **Validación estricta con Zod + JSON Schema.** Errores con path y mensaje claro, no silencio.
- **Versionado explícito.** El campo `version` permite evolución sin romper consumidores antiguos.
- **Local-first.** Cero referencias a URLs externas en runtime. Todos los conceptos están en `@m13/synth`.

## 2. Schema raíz

Un documento `.m13 v0.1` es un mapa YAML cuyo nivel superior tiene exactamente los siguientes campos:

| Campo | Tipo | Requerido | Default | Descripción |
|---|---|---|---|---|
| `version` | string | sí | `"0.1"` | Versión de la especificación. Debe coincidir con el runtime. |
| `name` | string | sí | — | Nombre interno de la escena (slug). Único dentro del proyecto. |
| `description` | string | no | `undefined` | Descripción libre legible por humanos. Útil para galería/UI. |
| `bounds` | vec3 | no | `[5, 3, 5]` | Mitades del bounding box del cuarto (x, y, z) en metros. El cuarto va de `-bounds` a `+bounds`. |
| `spawn` | vec3 | no | `[0, 0, -3.5]` | Posición inicial de la cámara. |
| `ambient` | objeto | no | defaults | Configuración de ambiente y niebla. Ver §6.1. |
| `light` | objeto | no | defaults | Luz puntual única (Fase 1). Ver §6.2. |
| `walls` | objeto | sí | — | Material de las 4 paredes. Ver §5.1. |
| `floor` | objeto | sí | — | Material del piso. Ver §5.1. |
| `ceiling` | objeto | sí | — | Material del techo. Ver §5.1. |
| `window` | objeto | no | `undefined` | Recorte rectangular en una pared. Ver §6.3. |
| `objects` | array de objeto | no | `[]` | Objetos colocados dentro del cuarto. Ver §5.3. |

> **Nota — campos no listados aquí:** se aceptan con warning `[m13/parser] campo desconocido: <path>`, pero no rompen el parsing. Ver §8.

## 3. Tipos primitivos

### 3.1 `vec3`

Array YAML de exactamente 3 números (en metros para posiciones/bounds, sin unidades para vectores arbitrarios).

```yaml
bounds: [5, 3, 5]
position: [0.0, -1.5, 0.0]
```

### 3.2 `rgb`

Array YAML de exactamente 3 números >= 0 interpretados como sRGB linealizado. Valores > 1 son válidos (HDR) — el propio spec usa `1.4` en luces de ejemplo; el tone mapping del shader los comprime.

```yaml
color: [1.0, 0.92, 0.78]
```

> No se aceptan strings hex (`"#ffffff"`), nombres CSS (`"white"`) ni cuatro componentes (alpha). Esto puede abrirse en v0.2.

### 3.3 `number`

Punto flotante. Algunos campos imponen restricciones adicionales (ver tabla del campo correspondiente).

### 3.4 `string`

Cadena UTF-8. Sin escape sequences ni interpolación.

### 3.5 `boolean`

`true` o `false` literal de YAML.

## 4. Conceptos (`@m13/synth`)

Un **concepto** es una unidad reutilizable de síntesis material/geométrica. Vive como módulo TypeScript en `packages/synth/src/concepts/<id>.ts` y se identifica por su **id en snake_case**.

### 4.1 Categorías de conceptos (`category`)

| Categoría | Aplicable a | Ejemplos |
|---|---|---|
| `wall` | Sólo paredes (`walls`) | `pared_yeso_blanco`, `pared_ladrillo_viejo` |
| `floor` | Sólo piso | `piso_madera_envejecida`, `piso_concreto_industrial` |
| `ceiling` | Sólo techo | (compartidos con `wall` por ahora) |
| `object` | Material de objetos | `metal_dorado_pulido`, `cuero_vintage` |
| `universal` | Cualquier superficie | `marmol_blanco_vetas`, `piedra_volcanica` |
| `object_geo` | Objeto con geometría propia (concepto geométrico) | `pedestal_marmol`, `lampara_colgante` |

> El runtime NO valida estrictamente la categoría contra el slot — un `wall` referenciado como `floor` compilará pero podría verse raro. La validación de categoría es advisory.

### 4.2 Estructura de un concepto

Cada concepto exporta (definido en `@m13/synth`):

```typescript
interface Concept {
  id: string;                    // 'pared_ladrillo_viejo'
  category: ConceptCategory;     // 'wall' | 'floor' | ...
  description: string;           // legible por humanos
  wgsl: string;                  // función mat_<id>(p, n, audioAmp) -> vec3<f32>
  wgslSdf?: string;              // sólo conceptos geo: función sdf_<id>(p, params) -> f32
  paramsSchema?: z.ZodObject;    // schema de params editables (Fase 1+)
  defaults?: Record<string, unknown>;
}
```

### 4.3 Catálogo `v0.1` mínimo

Al cerrar Fase 1, `@m13/synth` exporta 14 conceptos:

**Materiales (10):**
- `pared_yeso_blanco` (wall) — yeso neutral
- `pared_ladrillo_viejo` (wall) — ladrillo rojizo audio-reactivo
- `pared_concreto_pulido` (wall) — concreto gris speckle
- `pared_madera_oscura` (wall) — madera tinta café
- `piso_madera_envejecida` (floor) — madera con vetas
- `piso_concreto_industrial` (floor) — concreto pulido
- `piso_marmol_blanco` (floor) — mármol pulido
- `marmol_blanco_vetas` (universal) — mármol con vetas
- `piedra_volcanica` (universal) — piedra oscura
- `metal_dorado_pulido` (object) — dorado mate audio-reactivo
- `metal_bronce_pulido` (object) — bronce cobrizo
- `metal_oxidado` (object) — metal con óxido naranja
- `cuero_vintage` (object) — cuero envejecido
- `vidrio_esmerilado` (object) — vidrio esmerilado emulado

**Geométricos (4):**
- `pedestal_marmol` — round_box parametrizable + mármol
- `lampara_colgante` — cilindro con emisión inline
- `esfera_decorativa` — sphere con material configurable
- `cubo_basico` — box con material configurable

## 5. Superficies y objetos

### 5.1 Superficies del cuarto: `walls`, `floor`, `ceiling`

Cada uno es un objeto YAML con la siguiente forma:

```yaml
walls:
  concept: pared_ladrillo_viejo  # requerido — id de un Concept registrado
  params:                         # opcional — overrides del paramsSchema del concepto
    rustAmount: 0.6
```

| Campo | Tipo | Requerido | Descripción |
|---|---|---|---|
| `concept` | string | sí | ID del concepto. Debe existir en `@m13/synth`. |
| `params` | mapa | no | Overrides de parámetros editables del concepto. Validados contra `paramsSchema`. |

> Si `concept` no está registrado, el compilador lanza error `[m13/compiler] Concepto desconocido: "<id>"`. Si `params` no validan, error con path Zod.

### 5.2 Material para objetos: forma corta y forma extendida

Un `objects[*].material` puede ser:

**Forma corta (string):**
```yaml
material: metal_dorado_pulido
```

**Forma extendida (objeto con params):**
```yaml
material:
  concept: metal_dorado_pulido
  params:
    shimmer: 0.8
```

Las dos formas son equivalentes a nivel runtime — la corta es azúcar sintáctica para `{concept: <string>, params: {}}`.

### 5.3 Objetos (`objects[*]`)

Array de objetos colocados dentro del cuarto. Cada elemento:

| Campo | Tipo | Requerido | Default | Descripción |
|---|---|---|---|---|
| `id` | string | sí | — | Identificador único dentro de la escena (slug). |
| `kind` | enum | sí | — | Forma primitiva. Valores: `sphere`, `box`, `round_box`, `cylinder`, `torus`, `concept`. |
| `position` | vec3 | sí | — | Centro del objeto en coordenadas del cuarto. |
| `rotation` | vec3 | no | `[0,0,0]` | Rotación en **grados** (x, y, z) — implementada (orden de aplicación ZYX en el compilador). |
| `scale` | number \| vec3 | no | `1` | Escala uniforme o por eje. Para `sphere`: usa x como radio. Para `cylinder`: y=altura, x=radio. Para `torus`: x=major, y=minor. |
| `material` | string \| objeto | sí (excepto `kind: concept`) | — | Material aplicado. Ver §5.2. |
| `audio_reactive` | boolean | no | `false` | Si el objeto reacciona al amplitud del mic (`uniform audioAmp`). |
| `animate` | objeto | no | — | Animación periódica simple. Ver §5.4. |
| `concept` | string | requerido si `kind: concept` | — | ID de un concepto `object_geo`. Reemplaza la primitiva por su SDF. |

### 5.4 Animaciones (`objects[*].animate`)

Bloque opcional para animar el objeto:

```yaml
animate:
  mode: bob          # uno de: bob, rotate, pulse
  speed: 0.8         # número
  amplitude: 0.15    # número
```

| Campo | Tipo | Default | Descripción |
|---|---|---|---|
| `mode` | `bob` \| `rotate` \| `pulse` | — | `bob`: oscila en y. `rotate`: gira sobre su eje y. `pulse`: escala periódica (amplitude acotada a 0.9). Los tres implementados. |
| `speed` | number | `1.0` | Frecuencia. |
| `amplitude` | number | `0.1` | Amplitud (metros o radianes según mode). |

## 6. Ambiente, luz y window

### 6.1 `ambient`

```yaml
ambient:
  background: [0.05, 0.045, 0.04]   # rgb fondo (no usado directamente — fog domina)
  ambientColor: [0.08, 0.075, 0.07] # rgb luz ambiental constante
  tint: [1.05, 1.0, 0.92]            # multiplicador color final
  fogColor: [0.05, 0.045, 0.04]      # rgb del fog volumetric
  fogDensity: 0.015                  # densidad del fog (≥0). 0 = sin fog.
```

Todos los campos son opcionales y tienen defaults sensatos.

### 6.2 `light` (puntual única, Fase 1)

```yaml
light:
  position: [0, 2.5, 0]
  color: [1.0, 0.92, 0.78]
  intensity: 1.0
```

| Campo | Tipo | Default | Restricciones |
|---|---|---|---|
| `position` | vec3 | `[0, 2.5, 0]` | — |
| `color` | rgb | `[1.0, 0.92, 0.78]` | — |
| `intensity` | number | `1.0` | sin restricción (0 = apagada) |

> Fase 2 puede agregar `lights: [...]` para múltiples luces. v0.1 sólo una.

### 6.3 `window` (recorte en pared)

```yaml
window:
  position: [0, 0.5, 5]   # centro del recorte
  size: [1.4, 1.0, 0.5]   # mitades en x, y, z
```

Recorta un box SDF de las paredes en la posición indicada. Permite ver "afuera" (color del fog).

## 7. Determinismo y compilación

El compilador `compileScene(scene)` es **determinista**:

- Misma escena → mismo WGSL byte-por-byte.
- Conceptos referenciados se ordenan lexicográficamente por id antes de inyectarlos.
- Floats se serializan con 6 decimales fijos para evitar ruido (`0.300000000004` → `"0.300000"`).
- El hash SHA-256 del WGSL output es la clave de caché de shaders en `M13Engine`.

Esto permite:

1. Caché agresivo de pipelines compilados.
2. Reproducibilidad para debugging.
3. Validación CI: la misma escena nunca produce diff binario.

## 8. Validación

### 8.1 Pipeline de validación

```
YAML text
  ├─ yaml.parse() ──── (1) Sintaxis YAML
  └─ m13SceneSchema.safeParse() ──── (2) Tipos + restricciones Zod
        └─ post-checks:
             ├─ version === "0.1"   (3) Versión soportada
             ├─ campos top-level desconocidos → warning   (4) Política extensibilidad
             └─ concepts referenciados existen   (5) Resolución en compiler
```

### 8.2 Formato de errores

**Sintaxis YAML inválida:**
```
[m13/parser] YAML inválido: <yaml-lib error message>
```

**Validación Zod fallida:**
```
[m13/parser] Escena .m13 inválida:
  · objects.0.position — array must contain exactly 3 element(s)
  · light.intensity — Expected number, received string
```

**Versión no soportada:**
```
[m13/parser] m13 v0.2 no soportado por este runtime (se esperaba v0.1)
```

**Concepto desconocido (en compiler):**
```
[m13/compiler] Concepto desconocido: "pared_inventada". Asegúrate de que @m13/synth lo exporta.
```

### 8.3 Política de campos desconocidos

Por default el parser solo emite `console.warn` para claves desconocidas en el **nivel raíz**; en niveles anidados Zod las stripea en silencio (un typo `intencity:` dentro de `light` cae al default sin aviso). Para detectar typos en CUALQUIER nivel existe el modo estricto: `parseScene(yaml, { strict: true })` lanza error con el path exacto — lo usan el editor LLM y `tools/validate-scene.ts`. Ejemplo:

```yaml
version: "0.1"
name: test
walls: { concept: pared_yeso_blanco }
floor: { concept: piso_madera_envejecida }
ceiling: { concept: pared_yeso_blanco }
custom_field: foo   # ← warning, no error
```

Razón: permitir que herramientas externas (editor, dev tools) anoten metadata sin romper.

## 9. Política de extensión y versionado

### 9.1 Versionado del formato

El campo `version` es el contrato. Reglas:

- **Patch (`0.1` → `0.1.1`):** sin breaking changes. Optionalemente documentables en el changelog del spec. v0.1 no diferencia patch.
- **Minor (`0.1` → `0.2`):** agrega features manteniendo compatibilidad con docs `0.1`. El runtime v0.2 carga docs v0.1 con warning.
- **Major (`0.x` → `1.0`):** breaking. Los runtimes mayores no aceptan docs minores anteriores sin migration explícito.

> En v0.1, el runtime sólo acepta `version: "0.1"`. Cualquier otra → error claro.

### 9.2 Cómo añadir campos en v0.2 sin romper v0.1

1. **Campos opcionales en estructuras existentes** → no rompen. Ejemplo: agregar `objects[*].material_audio_band` en v0.2 es seguro porque v0.1 lo ignora con warning.
2. **Nuevas categorías de conceptos** → no rompen. Si v0.2 introduce `concept_neural`, los docs v0.1 no lo referencian.
3. **Nuevos campos top-level** → no rompen si son opcionales. Ej: `lights: [...]` en v0.2 como array de luces, con `light` v0.1 mapeable como `lights[0]`.
4. **Nuevo `kind` en objects** → no rompe. Ej: `kind: gaussian_splat` en v0.4.

### 9.3 Qué NO hacer en evolución

- Renombrar campos existentes (rompe).
- Cambiar el tipo de un campo (rompe). Ejemplo: si v0.2 cambia `intensity: number` a `intensity: object`, v0.1 docs rompen.
- Eliminar valores enum (rompe).

## 10. Tres ejemplos positivos (válidos)

### 10.1 Mínimo (`minimal_room.m13`)

Escena mínima con defaults — sin objects, sin window, sin description.

```yaml
version: "0.1"
name: minimal_room
walls:
  concept: pared_yeso_blanco
floor:
  concept: piso_madera_envejecida
ceiling:
  concept: pared_yeso_blanco
```

Tamaño: ~150 bytes. Renderiza un cuarto vacío con yeso, madera, yeso.

### 10.2 Intermedio (`sala_galeria.m13`)

Galería minimalista con esfera sobre pedestal.

```yaml
version: "0.1"
name: sala_galeria
description: "Galería de arte minimalista con esfera blanca sobre pedestal de mármol"
bounds: [6, 3.5, 6]
spawn: [0, 0, -4]
ambient:
  ambientColor: [0.12, 0.12, 0.13]
  tint: [0.98, 0.98, 1.02]
  fogColor: [0.06, 0.06, 0.08]
  fogDensity: 0.01
light:
  position: [0, 3, 0]
  color: [1.0, 1.0, 1.05]
  intensity: 1.2
walls:
  concept: pared_yeso_blanco
floor:
  concept: piso_marmol_blanco
ceiling:
  concept: pared_yeso_blanco
objects:
  - id: pedestal
    kind: concept
    concept: pedestal_marmol
    position: [0, -2.5, 0]
    scale: 1.0
  - id: esfera_blanca
    kind: sphere
    position: [0, -1.4, 0]
    scale: 0.4
    material:
      concept: marmol_blanco_vetas
      params:
        veinIntensity: 0.3
    animate:
      mode: bob
      speed: 0.4
      amplitude: 0.08
```

Tamaño: ~900 bytes.

## 11. Tres contraejemplos (inválidos)

### 11.1 Versión no soportada

```yaml
version: "0.2"   # ← no soportada por runtime v0.1
name: futurista
walls: { concept: pared_yeso_blanco }
floor: { concept: piso_madera_envejecida }
ceiling: { concept: pared_yeso_blanco }
```

**Error esperado:**
```
[m13/parser] m13 v0.2 no soportado por este runtime (se esperaba v0.1)
```

### 11.2 Concepto inexistente

```yaml
version: "0.1"
name: concepto_inventado
walls:
  concept: pared_de_chocolate    # ← no existe en @m13/synth
floor:
  concept: piso_madera_envejecida
ceiling:
  concept: pared_yeso_blanco
```

**Error esperado (en compile-time, no parse-time):**
```
[m13/compiler] Concepto desconocido: "pared_de_chocolate". Asegúrate de que @m13/synth lo exporta.
```

> El parser SÍ acepta este YAML — la validación de existencia es del compilador, no del schema Zod, porque el schema desconoce el registry de `@m13/synth`. Es por diseño: separación de preocupaciones.

### 11.3 Tipo inválido en campo numérico

```yaml
version: "0.1"
name: tipos_rotos
walls: { concept: pared_yeso_blanco }
floor: { concept: piso_madera_envejecida }
ceiling: { concept: pared_yeso_blanco }
light:
  intensity: "muy fuerte"   # ← string en lugar de number
objects:
  - id: obj_sin_position
    kind: sphere
    scale: 0.5
    material: metal_dorado_pulido
    # ← position faltante
```

**Error esperado:**
```
[m13/parser] Escena .m13 inválida:
  · light.intensity — Expected number, received string
  · objects.0.position — Required
```

## 12. Apéndices

### A. JSON Schema autogenerado

El archivo `v0.1.schema.json` (en este mismo directorio) es generado automáticamente desde el Zod schema con `pnpm gen:schema`. Se mantiene en sync mecánicamente — no editar a mano.

Para validar un `.m13` manualmente sin runtime:

```bash
# usando ajv-cli
npx ajv-cli validate -s m13-spec/v0.1.schema.json -d packages/examples/public/scenes/sala_galeria.m13.json
```

(Convertir YAML a JSON previamente con `yq` o similar.)

### B. Glosario

- **Concept** — unidad reutilizable de síntesis material o geométrica. Vive en `@m13/synth`.
- **SDF** — Signed Distance Field. Función matemática que define geometría implícita.
- **WGSL** — WebGPU Shading Language.
- **FBM** — Fractal Brownian Motion. Ruido procedural usado en muchos conceptos.
- **Audio-reactive** — propiedad que indica que el material/geometría debe modularse con la amplitud del micrófono (`uniform audioAmp`).

### C. Convenciones de naming

- IDs de conceptos: `snake_case` español (`pared_ladrillo_viejo`).
- IDs de objects en escenas: `snake_case` libre (`mesa_principal`, `lampara_1`).
- Nombres de escenas: `snake_case` (`sala_galeria`, no `Sala Galería`).
